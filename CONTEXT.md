## Проект
Telegram OSINT-бот «AGRIGAT OSTIN» — `unified-monitor/`. aiogram 3.x, SQLAlchemy 2, SQLite (локально) + Supabase (прод). Рабочий venv: `unified-monitor\.venv` (Python 3.13, полный набор зависимостей). Глобальный python — НЕполный, не для запуска бота.

## Что НЕ трогать / помнить
- **`_window()`/`DB_LOCAL_WINDOW` мы НЕ меняли** — пользователь против обрезки поиска по БД. Поиск должен идти по всей базе (все файлы). Локальные лимиты `limit=20`/`limit=5` — только на выдачу, не на охват.
- **Не изменять охват/обрезку поиска** — это чувствительная тема для пользователя.
- Не коммитить `.env`, `.env.txt`, `.env.local` (в .gitignore). `.env.example` — без секретов, ок.
- Не вставлять реальные ключи в код/README/коммиты.

## Проблемы «высокого уровня» (инфраструктурные, не код)
1. Supabase `ilike` по 2.1M строк → timeout 500 PGRST105 → fallback в локальное зеркало. Решение: выполнить `supabase/indexes_trgm.sql` в Supabase SQL Editor (ещё НЕ выполнено).
2. Himera привязан к IP — на Render IP не авторизован в ЛК Himera → возвращает `{"error":"invalid ip adress"}` (код корректно считает 0 затрат).
3. env-переменные в панели Render вводятся вручную (`sync: false`). Ключи уже на Render.
4. Один токен = один бот — одновременный polling на Render + локально даёт Conflict.
5. У пользователя ДВА supabase-проекта (qokujzqkeprvqnoxviuc и jzvmxqsfailsjqjkuxyb). Код читает только `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` (без `_2`). Нужно проверить, в каком проекте реальные 2.1M записей и где искать/индексировать.
